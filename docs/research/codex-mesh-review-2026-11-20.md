# Mesh and compatibility review by Codex — 2026-11-20

A review of the agent-mesh, hub, and compatibility designs by Codex (`gpt-6.2-astra`, high
reasoning effort), kept verbatim as a record.

**How to read it.** The reviewer ran the installed Codex binaries for configuration parsing
only; its findings about Codex *behaviour* come from reading the matching release source and
tests, and were not reproduced live by anyone. They are treated as strong leads to confirm in
spike S10, not as established fact. What was adopted, and where the reviewer and the current
design still differ, is recorded in [`pending.md`](../pending.md) and
[`10-agent-mesh.md`](../10-agent-mesh.md). Where this file and the docs disagree, the docs are
current.

---

**Keep the MCP bridge. Change the delivery contract before implementation.** On Codex 0.171.0, `turn/start` can steer a turn already in progress and return that turn’s ID. A successful RPC therefore does not prove YAAC started a separate turn for the message. [Codex active-turn test](https://github.com/openai/codex/blob/rust-v0.171.0/codex-rs/app-server/tests/suite/v2/turn_start.rs#L654) · [Mesh — Delivery](../10-agent-mesh.md)

**Verification boundary.** I ran the installed 0.170.0 CLI and the managed 0.171.0 executable. The latter parsed both MCP configurations below, accepted `tool_timeout_sec=86400`, and reported `mcp_connection_sharing` as under development and disabled. The sandbox denied access to the running daemon socket with `EPERM`. A separate stdio app-server stopped before initialization because its SQLite state required a writable filesystem. The behavioral findings below come from the matching 0.171.0 release source and upstream tests, which I read but did not run. I did not time a call, measure bridge memory, run Claude, or modify files.

## 1–6. Codex findings

1. **One thread can have its own MCP server.** Use a dotted key in `thread/start.params.config`, for example `{"mcp_servers.yaac":{"command":"/absolute/path/yaacd","args":["mcp"],"env":{"YAAC_TICKET":"…"}}}`. The HTTP alternative is `{"mcp_servers.yaac":{"url":"https://bridge.example/mcp","bearer_token_env_var":"YAAC_TOKEN"}}`. The latter names an environment variable available to Codex. A global registration makes the server available across threads, but does not by itself share a process. With sharing disabled, budget one stdio child per connected, loaded thread. With experimental sharing enabled, compatible registrations and negotiated server support can reuse a child. The upstream test compares process IDs across two threads. [Start handler](https://github.com/openai/codex/blob/rust-v0.171.0/codex-rs/app-server/src/request_processors/thread_processor.rs#L1301) · [Per-thread override test](https://github.com/openai/codex/blob/rust-v0.171.0/codex-rs/app-server/tests/suite/v2/thread_resume.rs#L194) · [Sharing test](https://github.com/openai/codex/blob/rust-v0.171.0/codex-rs/app-server/tests/suite/v2/mcp_connection_sharing.rs#L64)

2. **A shared bridge can distinguish model calls.** Ordinary `tools/call` requests carry `params._meta.threadId`, `sessionId`, and `callId`. The object at `_meta["x-codex-turn-metadata"]` carries `thread_id` and `turn_id`. Use `threadId` for the conversation. The separate direct `mcpServer/tool/call` RPC stamps `threadId` but does not promise a model turn. A shared endpoint can route on these fields after authenticating its caller. Raw MCP metadata supplied by an arbitrary client proves no identity. [Model call path](https://github.com/openai/codex/blob/rust-v0.171.0/codex-rs/core/src/mcp_tool_call.rs#L656) · [Turn metadata](https://github.com/openai/codex/blob/rust-v0.171.0/codex-rs/core/src/responses_metadata.rs#L452) · [Direct RPC](https://github.com/openai/codex/blob/rust-v0.171.0/codex-rs/app-server/src/request_processors/mcp_processor.rs#L801)

3. **The release default is 300 seconds.** Both 0.170.0 and 0.171.0 define that value, although the public MCP guide says 60 seconds. I found no separate fixed product maximum in the ordinary model-call path. `tool_timeout_sec` sets the per-server ceiling, and a shorter caller deadline wins where supplied. For YAAC, explicitly configure 60 seconds and cap a single `wait` at 45 seconds, reduced further for any shorter effective deadline. Return a durable cursor so a timeout or cancellation cannot consume a message. [0.170 constant](https://github.com/openai/codex/blob/rust-v0.170.0/codex-rs/codex-mcp/src/rmcp_client.rs#L125) · [0.171 constant](https://github.com/openai/codex/blob/rust-v0.171.0/codex-rs/codex-mcp/src/rmcp_client.rs#L125) · [Deadline selection](https://github.com/openai/codex/blob/rust-v0.171.0/codex-rs/codex-mcp/src/binding.rs#L440) · [Public MCP guide](https://developers.openai.com/codex/mcp/)

4. **Dynamic tools work per thread without MCP.** Opt into `initialize.capabilities.experimentalApi`, pass `dynamicTools` on `thread/start`, and answer `item/tool/call` on the app-server connection. The request includes `threadId`, `turnId`, `callId`, tool and arguments. The response carries `contentItems` and `success`. Codex persists the specifications on resume, but a connected client must still execute the calls. Both registration and dispatch are explicitly experimental. I would keep them out of the production dependency chain and retain MCP for Codex under D43. [App-server guide](https://developers.openai.com/codex/app-server/) · [Round-trip test](https://github.com/openai/codex/blob/rust-v0.171.0/codex-rs/app-server/tests/suite/v2/dynamic_tools.rs#L479) · [D43](../decisions.md)

5. **`developerInstructions` has two kinds of persistence.** Once the first turn materializes the developer message, it can survive in restored conversation history. The start-time override itself has no corresponding cold-resume guarantee. Cold resume builds configuration again and accepts `developerInstructions`. Rejoining an already-loaded thread explicitly ignores that override, and restored history can skip initial-context insertion. For an eligible thread created elsewhere, `thread/inject_items` has an upstream test that adds a developer message after an existing turn, persists it, and sees it in the next model request. Use that for a one-time YAAC introduction after acquiring control. [Session construction](https://github.com/openai/codex/blob/rust-v0.171.0/codex-rs/core/src/session/mod.rs#L1049) · [Context restoration](https://github.com/openai/codex/blob/rust-v0.171.0/codex-rs/core/src/session/mod.rs#L5578) · [Loaded-resume behavior](https://github.com/openai/codex/blob/rust-v0.171.0/codex-rs/app-server/src/request_processors/thread_processor.rs#L277) · [Injection test](https://github.com/openai/codex/blob/rust-v0.171.0/codex-rs/app-server/tests/suite/v2/thread_inject_items.rs#L546)

6. **An unattended turn needs a subscribed `yaacd` and an eligible recipient.** Start or resume subscribes the connection. An active turn can survive unsubscribe, and an idle thread can subsequently unload. Keep the target-side subscription through completion and pending requests. Preserve the destination’s approval settings, journal questions before notifying anyone, and provide an authorized human a way to answer a mesh-started turn. For agent-originated input, 0.171.0 supports `input: []` with `toolOutput: {"namespace":"yaac","name":"receive_message","output":"…"}`. This preserves the tool role in model input and history. On a busy thread, even tool output can join the active turn, so YAAC must own the queue. [Unsubscribe tests](https://github.com/openai/codex/blob/rust-v0.171.0/codex-rs/app-server/tests/suite/v2/thread_unsubscribe.rs#L234) · [Delegated-output test](https://github.com/openai/codex/blob/rust-v0.171.0/codex-rs/app-server/tests/suite/v2/thread_inject_items.rs#L702) · [Providers — Daemon backend](../04-providers.md)

## A. Five ranked design problems

| Rank | Scenario that breaks | Recommended change |
|---|---|---|
| **1. Delivery races the writer** | A terminal starts a turn after YAAC observes `idle`. Delivery steers the human’s turn. An idle terminal can also still own the conversation under D36. | Serialize human sends, mesh wakes, and wait consumption at the destination. Require demonstrable writer ownership at dispatch. A YAAC mutex cannot exclude an external client. Where the provider cannot guarantee ownership, keep the message queued. [Mesh — Delivery](../10-agent-mesh.md) · [Threads — Detecting it](../05-threads.md) |
| **2. A durable message can still start two paid turns** | The destination starts a turn and crashes before recording the turn ID. Replay finds the same message. Two separately retried messages can also arrive in reverse order. | Give each sender–recipient stream a sequence, deduplicate transactionally at each hop, and record dispatch intent before the provider call. Reconcile the returned turn against that intent or surface `outcome_unknown`. Track mailbox acceptance and turn consumption separately. Retain mesh transcript items through journal trimming. [Mesh — Receipts and durability](../10-agent-mesh.md) · [Protocol — Idempotency](../03-protocol.md) |
| **3. A valid-looking sender can be the wrong principal** | A renamed target or second Codex store changes what `devbox/codex:…` resolves to. A shared global credential or a forged display frame can make a peer appear authorized. Codex also allocates the native ID after the proposed identity prompt is constructed. | Address by immutable target ID, instance/store binding, and native thread ID. Issue an opaque attachment ticket before start, bind it to the returned ID before the first turn, and verify it against caller metadata. Stamp the envelope at `yaacd`, authorize `read_thread` separately, and keep peer text inside a structured payload. [Mesh — Addresses and identity](../10-agent-mesh.md) · [Providers — Store identity](../04-providers.md) |
| **4. Automatic wakes can run forever or strand every worker** | A three-agent cycle stays under every pairwise rate limit. Six waiting parents or six unattended approvals can occupy every execution slot. A notice that wakes its sender can feed the cycle. | Give each orchestration a durable root ID and finite allowances for turns, spawns, elapsed time and usage across targets. Reserve capacity for children. Make notices passive, completion results one-shot, and approval-blocked work visible to the parent and human. Preserve every pending approval. [Mesh — Safety and limits](../10-agent-mesh.md) · [Protocol — Thread control](../03-protocol.md) |
| **5. The hub owns work after acknowledging it** | The source drops its copy after the hub ACKs. A window restarts the hub during relay-store migration, or the hub exits idle and a target later originates work with no window open. Target journal replay alone cannot complete either route. | Keep the relay in a separately migrated durable store. Use a single-hub lock, quiesce and checkpoint before upgrade, replay unacknowledged deliveries, and keep a supervised hub available while unattended routing is enabled. Define target-originated relay/query and correlated ACKs on the existing stream. §03 currently permits only host-originated requests. [Architecture — Processes](../02-architecture.md) · [Mesh — The hub](../10-agent-mesh.md) · [Protocol — Messages](../03-protocol.md) |

## C. Compatibility changes before freezing v1

- **The Rust function table type-checks.** I checked a reduced version with `rustc 1.100.0`. The weak points are the fixed `StartRequest` shared across versions and the “no allocation” claim for `BoxFuture`. Give overridable steps stable domain inputs and a wire-level boundary that can represent an old shape. Pass the selected `&Dialect` into any step that invokes other overridable steps. Keep newest-as-base. [Compatibility — In Rust](../09-compatibility.md)
- **Exact whole-schema hashes conflict with additive evolution.** Two builds can legitimately speak the same version while one has an extra optional field. Hash an immutable baseline or make the full hash diagnostic. Gate optional operations on advertised capabilities and test unknown tagged variants with their payload intact. [Compatibility — Three rules and negotiation](../09-compatibility.md) · [Protocol — Design rules](../03-protocol.md)
- **Failed negotiation needs an executable management state.** Freeze a byte-level bootstrap fixture, frame bounds, exact error encoding, and the two permitted post-failure calls. Specify authenticated, idempotent handover and its ACK/disconnect behavior. Resolve the string `error.code` and omitted `jsonrpc` member before choosing a stock JSON-RPC codec. [Compatibility — Frozen core](../09-compatibility.md) · [Protocol — Messages](../03-protocol.md)
- **Test the peer that actually speaks each dialect.** The Rust client now lives in the hub. Run released old hubs against the current daemon as well as the current hub against released old daemons. A recorded client cannot expose old parser, scheduling, or reconnect behavior. Exercise failed negotiation, duplicate relay and handover during an ACK. [Compatibility — Tests](../09-compatibility.md) · [Architecture — Processes](../02-architecture.md)

## D. First working vertical slice

1. Prove S10 on a writable test installation with two real Codex threads, an echo MCP, recorded PIDs and `_meta`, a cold resume, and a concurrent external writer. Make ownership and attribution explicit pass criteria.
2. Build one local `yaacd` with stable addresses, attachment tickets, durable mailbox/outbox, operation IDs and a per-thread dispatcher.
3. Attach the three initial MCP tools to Codex over stdio and Claude through its SDK. Demonstrate **Codex → Claude → Codex** on one target, with the peer identity visible in both transcripts.
4. Add a headless hub and a second target over its single stream. Close the window, send across targets, interrupt the link after an ACK, and demonstrate one logical receipt and one recipient turn.
5. Add runtime model discovery and cross-target spawn using a destination-validated directory, a finite root budget, and one completion result.
6. Add bounded `wait`, approval journaling, and a minimal window showing both transcripts, workers and pending human requests. Exercise a busy recipient, an external owner, an unattended approval, and a hub restart before expanding the tool list.
