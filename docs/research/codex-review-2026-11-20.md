# Design review by Codex — 2026-11-20

An independent review of the first draft of these docs, written by Codex (`gpt-6.2-astra`, high
reasoning effort) at the project owner's request. It is kept verbatim as a record.

**Read it with two things in mind:**

- It reviewed the **first draft**. Most of what it found has since been folded into the docs;
  [`decisions.md`](../decisions.md#design-review) says what was adopted and what is still open.
  Where this file and the docs disagree, the docs are current.
- Its factual claims about Codex were re-tested before being adopted. Confirmed independently:
  the control socket speaks WebSocket; `Thread.id` versus `sessionId`; `turnId` on interrupt and
  steer; `thread/revert` leaving files alone; paged `model/list`; default source filter on
  `thread/list`; the SDK running `exec --experimental-json`; Claude's
  `applyFlagSettings({ effortLevel })`. Its claims about multi-client behaviour come from its
  reading of Codex's source and tests and were **not** reproduced live — spikes S5 and S7 do
  that.

---

## 1. Verdict

I would keep the decided architecture and hold M1 until the team proves who owns a live thread, who can answer its approvals, and how a client reconstructs state after a disconnect. The largest risk is treating a socket, a session store, a running agent, and a durable transcript as interchangeable. Codex 0.170.0 already has concrete cases where that assumption opens the wrong conversation, rejects a resume, or lets another client resolve a prompt YAAC still displays.

## 2. Design flaws and risks

Ranked by the cost of discovering them late.

| Severity | What breaks and when | Recommended change |
|---|---|---|
| **Critical · Thread identity and write ownership** | Codex `Thread.sessionId` is shared by threads in a session tree. Using it as the session key can merge distinct conversations. Even with the correct `Thread.id`, two instances can list the same store, while only one process owns the live writer. Attributing unknown sessions to the default instance can route Resume to a daemon that rejects it. Editing a socket can also silently repoint old sidebar entries at a different home. [05 · Identity](../05-threads.md) | Keep D5. For Codex, define YAAC’s provider session key as **`Thread.id`**. Persist the immutable instance binding and the observed store identity. Record which endpoints can see the thread separately from which endpoint can drive it. Revalidate home/account on endpoint edits. Show ambiguous or externally owned threads read-only until ownership is established. |
| **Critical · Approvals and concurrent controllers** | A terminal or another app on the same Codex daemon can receive and answer the same approval. A cached `pending` item can outlive the upstream request. A late Stop can hit the next turn if YAAC’s adapter accepts only a session ID. Closing the tab can also strand an approval if the provider subscription follows UI visibility. [03 · Messages and Turns](../03-protocol.md) · [04 · The contract](../04-providers.md) | Keep the upstream subscription for every YAAC-controlled active turn, including while all UIs are detached. Carry the native turn ID through start, steer and interrupt. Scope request IDs to the upstream server generation and thread. Support pending, answer submitted, resolved elsewhere, expired, and outcome unknown. Claim a YAAC response atomically and reconcile it with upstream resolution. Render the actual requested scope and permitted decisions. |
| **Critical · Replay and retried mutations** | If events 399–410 collapse into one `itemUpdated` for a slow client, the promised `seq + 1` invariant is broken. Events can arrive between `reset`, paged `thread/read`, and subscription. A restarted daemon can reuse sequence 412 for different content. A dropped response after first send can duplicate a thread or a paid turn even when the client generated an ID. The SDK fallback cannot reconstruct an evicted transcript from history. [03 · Threads, Subscriptions and replay, Backpressure](../03-protocol.md) · [05 · Local cache](../05-threads.md) | Give each event stream an epoch. Return a snapshot watermark and a cursor bound to that snapshot, then deliver events strictly after the watermark. Assign sequence numbers after common coalescing. Per-client collapse must explicitly cover a sequence range or force a reset. Commit cache changes and cursor together. Journal operation IDs and outcomes for create/first-send, fork and respond as well as turn start. If the harness accepted an operation and the result cannot be recovered, surface **outcome unknown** and suppress automatic resend. |
| **High · Persistent daemon upgrades** | Versioned socket names prevent a bad handshake, but two YAAC versions can still own the same registry, uploads, approvals and harness sessions. Two application builds can also share a protocol version and reach the older running implementation after installing the newer bundle. Reinstalling once does nothing to resolve either case. [02 · Daemon lifecycle](../02-architecture.md) · [03 · Versioning](../03-protocol.md) | Keep D15’s exact wire-version check. Separately identify the build and persistent-state format. Elect one serving owner per target/user under a startup lock. On incompatible upgrade, drain active work and pending requests before transfer. A second UI should see the incumbent build and a clear busy result. Test simultaneous first launch, crash during takeover, and an older UI reconnecting. |
| **High · One stream has a latency floor** | At 1 Mbit/s a single 256 KiB frame takes about **2.1 seconds** to serialize. An approval answer or interrupt queued behind four such upload frames can wait over eight seconds. The reverse direction has the same problem with a large history response. A full-item replacement can itself exceed the 1 MiB frame limit. The 100 MB checksum spike would pass all of these cases. [02 · Single-connection rule](../02-architecture.md) · [03 · Framing](../03-protocol.md) · [08 · S2](../08-roadmap.md) | Keep D3. Schedule control and bulk work separately in **each direction of the same stream**. Limit bytes already handed to the writer, use receiver credit, adapt chunk size to link speed, and page large outputs by bytes. Measure p95 Stop/Respond latency under simultaneous upload and history download. Settings’ “test connection” should use the active connector or serialize behind it. |
| **High · Stage 0 and platform assumptions** | `-T` removes the PTY, but shell startup output can still precede `YAAC0`. A shell reader can consume bytes intended for the next protocol phase. Two installers can race, or a disconnect can leave a partial “installed” bundle. A text-safe WSL fallback negotiated after bootstrap cannot save a corrupted binary `PUT`. A native Windows SSH server can start a non-POSIX shell. [02 · Transports and Bootstrap](../02-architecture.md) · [Microsoft’s Windows OpenSSH configuration](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh_server_configuration) | Since Q2 assumes Node, give the shell only the job of finding and launching Node. Let one byte-oriented process own stdin through install and attach. Use bounded startup diagnostics, an explicit ready boundary, a private temporary file, full digest verification, an install lock and atomic rename. Select any text-safe encoding **before** bundle bytes. Specify supported SSH remote shells and test non-login `PATH`, noisy startup, interrupted install and concurrent install. |
| **High · Capability union makes false promises** | A backend accepting image syntax says nothing about the selected model’s vision support. Claude’s missing model flag becomes a blanket yes. The Codex SDK’s free-text model has no authoritative modality data. `Reasoning` alone enables an effort control even when the adapter cannot change effort. A single `Rewind` flag can describe either conversation truncation or restoring files, two materially different user actions. [04 · Capabilities and Models](../04-providers.md) · [07 · Control row](../07-ui.md) | Keep D8 and the provider-neutral UI. Have the adapter compute **effective operations** from backend support, model evidence, account/policy and current thread state. Represent unknown explicitly. Include operation parameters such as allowed efforts, grant scopes, supported input formats and whether rewind affects files. Validate the selected model and descriptor revision at send time, and report the settings the harness actually applied. |
| **High · Attachment identity, reachability and retention** | A draft can switch targets after upload began. A local file can change after hashing. A path in `~/.yaac/uploads` may be unreadable from the harness sandbox, and deletion of the source thread can break a fork that still references it. A second host has no protocol operation to fetch the thumbnail it is expected to display. The short-hash, per-thread filename layout also does not by itself implement global deduplication. [06 · Flow, Upload store and Images](../06-attachments.md) · [03 · Uploads](../03-protocol.md) | Bind upload handles to a target/store identity. Invalidate or re-upload on retarget. Use a full-digest immutable blob with per-draft/thread references and an explicit commit at send. Snapshot local files for D10. Verify readability in the selected execution environment without broadening permissions. Bound file bytes, decoded pixels and concurrent encodes. Add a bounded thumbnail read on the existing stream and specify cleanup of partial uploads. |
| **High · Fork cannot always deliver the advertised history** | Two Codex instances of the same kind can use disjoint homes. The destination’s `thread/fork` then cannot resolve the source. An SDK-only source with an evicted host cache cannot export a complete transcript. Even a native fork does not clone the working directory, running tools or outstanding approvals. A transcript file can also carry private tool arguments into a different provider account. [05 · Fork](../05-threads.md) · [07 · Fork control](../07-ui.md) | Select the mechanism for the **source/destination pair**. Require proven native reachability for native fork. Otherwise require an exportable snapshot at a named completed turn, a readable destination, and an explicit account/provider destination. Preview what crosses that boundary. Pin the transcript and its referenced files to the child. Disable fork with a reason when reconstruction is incomplete. Display inherited history from that frozen snapshot. |
| **High · Windows and WSL process lifetime** | A detached child can still be killed by a Windows job or SSH session cleanup. WSL shutdown terminates the distro. A native Windows path, a WSL path and a Linux remote path have different semantics even if they designate the same disk. A Rust host `PathBuf` plus a separator does not encode those distinctions. [02 · Local, WSL and Daemon lifecycle](../02-architecture.md) · [05 · Thread summary](../05-threads.md) · [WSL command reference](https://learn.microsoft.com/en-us/windows/wsl/basic-commands) | Specify survival across UI/bridge exit while the target OS remains alive. Test last-bridge exit, logout, sleep, distro shutdown and restart separately. Define per-platform detach, socket/pipe permissions and stale-owner recovery. Carry target-native paths as typed opaque values and resolve them on-target. Test spaces, Unicode, UNC paths, Windows executable wrappers, and binary WSL stdin/stdout in both directions. |
| **Medium · egui and memory budgets** | Virtualizing rows does little for a single 20 MB tool result or an unclosed code fence that grows every frame. Reparse of the growing block can become quadratic. Late Markdown reference definitions can change earlier rendering. Width, DPI or font changes invalidate measured heights and can move the reader’s scroll position. Synchronous SQLite, hashing or image decode on the single I/O thread can stall every target while the UI still appears responsive. [07 · Rendering and memory](../07-ui.md) · [02 · Footprint budget](../02-architecture.md) | Page and cap bytes **within** an item. Render a bounded streaming tail, then perform a final conforming parse. Anchor scrolling by item and offset. Bound text layouts, snapshots, decode buffers and GPU textures by bytes. Use bounded workers for blocking work. Extend S1 to a giant item, resize during streaming, many open threads, high DPI and thumbnail churn. Measure the whole local process tree, including `yaacd connect`, alongside the host-only budget. |

## 3. Codex-specific corrections

**Verification scope.** I read `README.md`, `CLAUDE.md`, and every file under `docs/`. The installed CLI reports **0.170.0**. I ran the app-server, daemon, proxy, schema-generator, remote-control and exec help commands. A previously generated local JSON schema has the **same Git blob hash** as the official `rust-v0.170.0` schema, `762933428ea1a1c554d21eee107722f5382f70f5`. I also inspected the locally cached published SDK **0.171.0** implementation and declarations. `daemon version` was denied access to the live socket, and a fresh stdio server exited on the read-only filesystem. The multi-client findings below come from the matching release source and integration tests. I did not run a live approval, fork, Windows or WSL experiment. No files were changed. [Tagged protocol schema](https://github.com/openai/codex/blob/rust-v0.170.0/codex-rs/app-server-protocol/schema/json/codex_app_server_protocol.schemas.json)

- **The proxy is a byte relay. The control socket speaks WebSocket.** The transport names, management commands and `proxy --sock PATH` in the research doc check out. The private `stdio://` child consumes JSONL. The Unix listener expects an HTTP Upgrade followed by WebSocket frames. The proxy copies bytes in both directions, so sending a JSONL `initialize` into its stdin fails. Implement the WebSocket client on the target side. On each Codex connection, send `initialize` with client information and negotiated capabilities, then `initialized`. This is separate from YAAC’s D15 handshake. [04 · Daemon backend](../04-providers.md) · [Codex transport guide](https://developers.openai.com/codex/app-server/) · [0.170 proxy implementation](https://github.com/openai/codex/blob/rust-v0.170.0/codex-rs/stdio-to-uds/src/lib.rs)
- **A socket selects a listener. `CODEX_HOME` selects default management paths and state.** The managed CLI derives its default socket and management directory from the resolved home. `daemon start` exposes no per-socket selector. A separate managed home or an explicitly launched `app-server --listen unix://PATH` can provide another endpoint. Changing the proxy’s environment does not reconfigure an existing server. `initialize` returns the server’s `codexHome`, platform and user agent. Record those, and distinguish the running server version from the installed CLI. Separate homes also require deliberate configuration/auth setup. The “thread keeps working” fallback rule needs a store, ownership and capability check. [04 · Instance configuration and Backend selection](../04-providers.md) · [Daemon path selection](https://github.com/openai/codex/blob/rust-v0.170.0/codex-rs/app-server-daemon/src/lib.rs#L358) · [Cross-process writer-conflict tests](https://github.com/openai/codex/blob/rust-v0.170.0/codex-rs/app-server/tests/suite/v2/thread_resume.rs#L332)
- **Clients have independent connections and share a runtime.** Two clients initialize independently and can reuse the same outbound RPC ID. Each receives its own RPC response. There are global lifecycle notifications and separately scoped thread events. `thread/list` and `thread/read` are discovery/history operations. `thread/start`, `thread/resume` and `thread/fork` establish live subscriptions for the caller. Resuming an already loaded thread on that daemon rejoins it. There is no general Codex `thread/subscribe {afterSeq}`. Unsubscribe is per connection. Release tests show an active turn can continue after unsubscribe, and a thread with no subscribers becomes eligible for unload after it is idle. YAAC needs its own event replay and must reconcile sessions created in other processes. [Research · App-server and daemon](harness-surfaces.md) · [Connection routing tests](https://github.com/openai/codex/blob/rust-v0.170.0/codex-rs/app-server/tests/suite/v2/connection_handling_websocket.rs#L73) · [Unsubscribe tests](https://github.com/openai/codex/blob/rust-v0.170.0/codex-rs/app-server/tests/suite/v2/thread_unsubscribe.rs)
- **Ordinary approvals can have several recipients and one resolution.** The server sends the same thread-scoped request ID to subscribed connections and keeps one pending callback. The first accepted reply consumes it. Resume can replay still-pending command and file approvals. `serverRequest/resolved` can also mean the request was cleared by a turn transition. It does not prove that this UI’s user approved. There are exceptions to fan-out: `humanCommand` requires an eligible `requiredHumanApproval` client with experimental API support, and the user-verification elicitation has a single owner and is excluded from ordinary replay. A generic Allow/Deny card cannot faithfully implement all these protocols. [03 · Messages](../03-protocol.md) · [Request routing, replay and callback ownership](https://github.com/openai/codex/blob/rust-v0.170.0/codex-rs/app-server/src/outgoing_message.rs#L388) · [Approval replay tests](https://github.com/openai/codex/blob/rust-v0.170.0/codex-rs/app-server/tests/suite/v2/thread_resume.rs#L5925)
- **The documented method names largely check out. Their fields change the adapter design.** The matched schema contains 109 client request methods, including the listed history, fork, control and model calls. `Thread.id` identifies the conversation, `sessionId` identifies its session tree, and `forkedFromId` records fork lineage. `turn/start` returns a turn, can steer an active turn, and documents model, effort and policy overrides as applying to subsequent turns too. `turn/steer` requires `expectedTurnId`, and interrupt requires `turnId`. `clientUserMessageId` alone establishes no crash-safe exactly-once guarantee. `thread/list` cursors paginate a result; source filters default to interactive sources and archives require a separate query. `thread/revert` truncates paginated conversation history and leaves local file changes in place. [04 · Codex mapping](../04-providers.md) · [Tagged wire types](https://github.com/openai/codex/tree/rust-v0.170.0/codex-rs/app-server-protocol/schema/typescript/v2) · [Turn implementation](https://github.com/openai/codex/blob/rust-v0.170.0/codex-rs/app-server/src/request_processors/turn_processor.rs)
- **Model and input claims are substantially verified.** The schema has a nonempty open reasoning-effort string, per-model supported efforts, `inputModalities` with the documented text/image default, and text/image/audio modality tags. `UserInput` also supports `skill` and `mention`. `model/list` is paged, can include hidden entries and can target a configured `modelProvider`; refresh must exhaust the relevant pages before declaring a cached model gone. A schema field or method establishes a wire shape. It cannot establish that an account, a selected model or current policy enables the operation. [04 · Models are never hardcoded](../04-providers.md) · [Tagged schema](https://github.com/openai/codex/blob/rust-v0.170.0/codex-rs/app-server-protocol/schema/json/codex_app_server_protocol.schemas.json)
- **The SDK cannot implement `createThread() -> SessionId` as written.** In the inspected package, `startThread()` creates a handle with a null ID. Its first streamed exec emits `thread.started`, which supplies the ID. The package literally launches `exec --experimental-json`. Its item events, local-image input, abort signal, binary override and missing list/history/fork/interactive-approval APIs match the research. The CLI independently exposes `exec fork`. SDK model and effort are thread-handle options, and supplying SDK `env` replaces the inherited environment. Combine first send with thread materialization, and construct the intended child environment explicitly. Cross-backend continuation, transparent recovery and the one-file bundle remain unverified end to end. [04 · Contract and SDK backend](../04-providers.md) · [Research · Codex SDK](harness-surfaces.md)

One adjacent correction affects S6. The cached Claude Agent SDK 0.3.329 declarations explicitly document `query.applyFlagSettings({ effortLevel })` for a live streaming query. Test the effective value, policy limits and installed CLI compatibility before implementing close-and-resume for an effort change. [04 · Claude SDK backend](../04-providers.md)

## 4. Gaps

- **Durability of user-authored data.** Drafts are the only copy of unsent work, yet “clear cache” and a schema change can delete them. Give drafts and pending operation receipts their own durable storage and migration policy. Define where original input parts and attachment chips can be recovered when a second host reads a harness transcript containing only the transformed prompt. [05 · Local cache](../05-threads.md) · [06 · File parts](../06-attachments.md)
- **Privacy across accounts and targets.** “No credentials on the host” leaves transcript previews, tool output, cached images and drafts on disk. Define who can see cached material after an account change, target replacement, removal or workstation handoff. Apply the same policy to SQLite side files and diagnostic logs. [02 · Security](../02-architecture.md)
- **Index reconciliation and deletion.** Neither a paged harness listing nor a stream of notices from one daemon supplies the promised week-long change token. Specify an authoritative scan, stable pagination, tombstones, token expiry and recovery after a failed or partial scan. A transient provider failure must never remove its entire sidebar subtree. [05 · Discovery](../05-threads.md)
- **Operational diagnosis and resource exhaustion.** Define a way to distinguish SSH authentication failure, startup noise, Node/bundle mismatch, provider writer conflict, full disk and a stalled reader. Set deadlines, an active-session/process cap, upload quotas and redacted diagnostics available over the existing stream. These failures need different recovery actions. [02 · Reconnection](../02-architecture.md) · [03 · Errors](../03-protocol.md)
- **Accessible input and approvals.** The keyboard table does not specify IME composition versus Enter-to-send, focus when an approval arrives, keyboard-only approval inspection, or accessible names and states for the virtualized thread tree. Test those on both host platforms before committing to the composer and card widgets. [07 · Composer and Keyboard](../07-ui.md)

## 5. Questions for the owner before implementation

| Question | Options and recommendation |
|---|---|
| **What recovery guarantee is public after `yaacd` crashes between harness acceptance and recording the result?** | Automatic retry, durable reconciliation, or explicit uncertain outcome. **Recommend durable reconciliation where the provider exposes evidence, then uncertain outcome.** A second paid turn or duplicate fork is worse than asking the user to inspect one ambiguous send. |
| **Who owns a thread discovered through two instances, and what does editing an endpoint mean for old threads?** | Choose the first/default instance, expose duplicate conversations, or persist one binding with endpoint aliases. **Recommend one immutable binding, observed aliases, and explicit rebind after store verification.** This preserves D5 and gives the registry a concrete responsibility. |
| **Can a YAAC upgrade interrupt someone else’s running work?** | Immediate replacement, independent versioned writers, or one serving owner with a drain period. **Recommend drain and exclusive takeover.** Define what the newer UI can show while an older owner is still running or awaiting approval. |
| **What history must YAAC guarantee on a backend without history reads?** | Store a bounded or durable normalized history on-target, promise only a live view, or require a richer backend for history-dependent operations. **Recommend the richer backend for full history and fork.** Expose SDK-only recovery limits before a conversation begins. If full fidelity on SDK is mandatory, approve target-side storage now. |
| **What consent boundary applies to paste and handoff?** | Transfer immediately on paste/selection, stage locally until the destination is fixed, or require confirmation for every operation. **Recommend staging while the target is editable and explicit confirmation for a cross-account/provider transcript export.** Show the destination, cutoff and included material. |
| **Which remote launch environments are supported?** | POSIX SSH targets only, a separate Windows SSH launcher, or user-configurable launch commands. **Recommend specifying POSIX SSH for the first bootstrap, with native local Windows and WSL explicitly tested.** If Windows-over-SSH is required for MVP, settle its launcher and stream tests before S3. |

## 6. Position on Q1–Q10

| Question | Position |
|---|---|
| **Q1 · Turn survival** | **Agree.** Preserve running work across UI or connection loss. Make target shutdown, harness death, daemon crash and a turn waiting for human input separate observable outcomes. |
| **Q2 · Node runtime** | **Agree.** Require a tested Node version for MVP and probe it in the actual noninteractive launch environment. This also lets Node own the binary bootstrap. |
| **Q3 · Claude daemon** | **Agree on SDK-first, disagree on unconditional continuation.** List daemon-supervised sessions, but require the active worker to relinquish ownership or a supported live-attach path before offering Continue. |
| **Q4 · Sidebar population** | **Agree.** Show discoverable sessions with account/store provenance and availability. Explicitly classify YAAC-created SDK sessions as user-initiated so the default programmatic filter does not hide the user’s own chat. |
| **Q5 · Handoff** | **Agree.** Use a deterministic transcript at a completed turn, preview it, and retain it for the child. An incomplete or inaccessible source must change what the dialog offers. |
| **Q6 · Composer** | **Agree.** Style editable source in place. Preserve caret position, selection, undo and IME behavior, and bound formatting work on large pastes. |
| **Q7 · SSH** | **Agree.** Use system OpenSSH. Test GUI askpass, first-use and changed host keys, jump hosts and cancellation on Windows and Linux while stdout carries the protocol. |
| **Q8 · ACP** | **Agree.** A custom host protocol has clear jobs in target multiplexing, replay and binary transfer. Keep ACP at the provider boundary. |
| **Q9 · Private Codex app-server** | **Agree with daemon → private stdio app-server → SDK** for an implicit instance whose daemon is genuinely absent. Preserve explicit-socket failure and distinguish absence from access denial, incompatibility and active-writer conflict. Never start, update or stop the user’s shared daemon. |
| **Q10 · Smaller items** | **macOS:** agree with best-effort builds and no release commitment. **Two UIs:** disagree with leaving concurrency untested; ship one controlling UI plus observers or test competing mutations before M1 exits. **Uploads:** prefer the durable target store, pin referenced content and expire unreferenced blobs after a configurable grace period. **Permissions:** agree with harness defaults and display the effective sandbox, approval policy and reviewer returned for the thread. |
